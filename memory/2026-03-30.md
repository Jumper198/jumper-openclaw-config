# 2026-03-30 获客系统迭代：Nano Banana Pro 原生海报与发帖链路抢修

## 1. 战略与工具链对齐
- **确认核心需求**：Jumper 的一人公司获客矩阵（小红书），核心痛点是需要极简 SaaS 美学的“纯文字排版长图”或带品牌 IP（机械小红虾）的质感干货图。
- **纠偏记录**：系统在此之前错误尝试过使用 Python `Pillow` 硬编码排版文字，导致了小红书 CDN 报错（“图挂了”）。
- **终极解决方案**：**永远使用 Nano Banana Pro (Gemini 3 Pro Image) 处理所有文字排版图文**。由于 OpenClaw 网关默认工具 30 秒超时会导致 Pro 模型进程强杀（terminated），改用自定义 Python 后台脚本 (`timeout=120s`) 挂起调用，解决了所有的网络和限时中断问题。
- **输出成果**：成功稳定输出无错别字、自带极简呼吸感排版并内嵌 OpenClaw 机械红虾 3D Logo 的高质量海报。

## 2. 小红书发帖自动化（xiaohongshu-mcp macOS 修复）
- **安全隔离区分**：明确区分了用于“语料爬取”的沙盒高危工具 `opencli-rs`，和用于“真实账号发帖”的安全组件 `xiaohongshu-mcp`。
- **环境坑点修复**：`xiaohongshu-mcp` 的 `start-mcp.sh` 原先存在强制检测 `Xvfb` (Linux 虚拟桌面) 的逻辑，导致在 Jumper 的 macOS (arm64) 环境中无法启动并报 `未检测到桌面环境` 的错误。
- **代码重构**：强行魔改了 `start-mcp.sh`，删除了 `ensure_display` 验证逻辑，使其直接复用 macOS 原生图形环境，顺利打通了 `mcp-call.sh publish_content` 接口，完成了今天的小红书第一发。

## 3. 下一步架构演进
- **评论与线索监控**：当前系统已具备主动 Pull-based 监控的能力。后续可将 `user_profile` 与 `get_feed_detail` 加入 `HEARTBEAT.md` 进行轮询，一旦监测到目标触发词（如“获客”），自动私信 SOP 或回复线索，实现真正的“防漏单获客机器”。
